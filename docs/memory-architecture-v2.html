一、核心发现

当前所有记忆只按创建时间区分 hot/cold，但项目级知识（架构决策、核心模式）

不存在"过期"概念——半年前写的 project_context 今天仍然重要。

缺失的维度：耐久度——分永久/热/冷，而非仅分新旧。

二、新增：四层耐久度分层

L-PERSIST
持久层 · 永不衰减
project_context / 架构决策 / 核心模式 · importance≥8 或 pinned=True
每 turn 无条件注入，不占检索配额
L-HOT
热层 · 7 天窗口
近期决策、教训 · HOT.md 独立索引 · 优先检索
Dream 只扫这一层
L-CODE
代码索引 · 随代码更新
函数签名、调用链、模块依赖 · CodeGraphContext (KùzuDB 图数据库)
独立 MCP Server，与记忆索引并列
L-COLD
冷层 · 长期衰减
所有历史记忆 · fallback 检索 · decay_score(180天)
兜底，被挤到 hot/cold 边界下的

三、before_turn() 改后流程

查询→ 1. PERSIST 无条件注入→ 2. HOT 优先检索→ 3. COLD fallback→ 4. CODE 按需查询
