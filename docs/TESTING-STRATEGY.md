# 记忆检索测试策略 — 按生长阶段

Sisyphus 是一个从零开始喂养的个人记忆系统。测试不应该用一个固定 benchmark
跨所有阶段跑，而应该**模拟记忆从无到有的生长过程**。

每个阶段的目标、指标和触发条件都不同。

## 阶段 1: 种子期 (< 20 条记忆)

**场景**: 用户刚开始用，记忆很少，每句话都是全新的。

**指标**: 最近 5 条的 @1 = 100%（刚记的就该记得）

**测试**: 每创建 5 条新记忆，用这 5 条记忆的 title 和 content 生成简单 query
（比如从 content 中提取关键词），跑一轮 recall。

**通过标准**: 所有新记忆都能被精确召回。

## 阶段 2: 成长期 (20-100 条)

**场景**: 同一 topic 下开始出现相似但内容不同的记忆，混淆风险出现。

**指标**: @1 ≥ 80%，同时监控"长尾遗忘"——30 天前的老记忆是否被淹没。

**测试**: 每周自动触发 abc 测试。ab 测试分为两类：
- **同 type 内**: 随机选 3 个 type，每个生成 3 条 query，验证同 type 下不会搞混
- **跨 type**: 随机选 5 个 type 各 1 条 query，验证跨 type 不会漏

**通过标准**: 同 type @1 ≥ 70%，跨 type @1 ≥ 90%。

## 阶段 3: 成熟期 (100-500 条)

**场景**: 记忆量上来了，decay_score 开始有区分度，旧记忆和新记忆的区别变得重要。

**指标**: 同 type @1 ≥ 70%，decay 验证通过。

**测试**:
- 随机抽样 50 条记忆生成 query，跑 abc
- 对比 decay 启用 vs 不启用，验证旧记忆不会错误排到新记忆前面
- 检测 `_tokenize` 单字 fallback 是否引入了噪声

**通过标准**: abc @1 ≥ 70%，decay 不引入新 miss。

## 阶段 4: 饱和期 (500+ 条)

**场景**: 内存规模上来了，BM25 开始吃力，Reranker 激活条件触发。

**指标**: @1 ≥ 70%，Reranker 带来 ≥ 5% 提升。

**测试**:
- 全量 abc
- 对比 BM25 vs BM25+BCE，确认 reranker 有收益
- 单 type 下 docs > 20 时单独测该 type

**通过标准**: reranker @1 - BM25 @1 ≥ 5pp。

## 测试触发机制

| 触发方式 | 频率 | 内容 |
|----------|------|------|
| 写操作触发 | 每 5 条新记忆 | 阶段 1 测试 |
| 定时触发 | 每周 | 阶段 2-4 测试 |
| 手动触发 | 按需 | 全量 abc |

## 测试脚本位置

```
tests/
  test_growth_stage1.py   ← 种子期
  test_growth_stage2.py   ← 成长期
  test_growth_stage3.py   ← 成熟期
  test_growth_stage4.py   ← 饱和期
```
