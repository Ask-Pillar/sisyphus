# Nexus 借力-内化方案

## 策略：先借后替，分三批

每个能力经过三个阶段：
- **挂载期**（1-2 月）→ 直接用现成的，最快上线
- **观察期**（3-4 月）→ Nexus 记录使用数据，Dream 分析模式
- **替换期**（5-6 月）→ 蒸馏完成，内化为 internal，摘掉外部

## 第一批：基础设施（本月）

直接用，不替换。这些都是成熟库，自研无意义。

| 能力 | 现成方案 | 原因 |
|------|----------|------|
| 全文检索 | SQLite FTS5 | 已有，不替换 |
| PDF 解析 | pymupdf | 纯文本提取，0 依赖 |
| DOCX 解析 | python-docx | 成熟稳定 |
| 图片 OCR | tesseract | 免费、纯 CPU |
| 中文分词 | jieba | 已有，不替换 |
| HTTP 服务 | aiohttp | MCP Server 用 |
| 配置管理 | PyYAML | config.yaml |
| 容器化 | Docker Compose | 已有 |

**投入**：零。这些库已经在我们依赖里或 pip install 即可。

## 第二批：Agent 能力（1-3 月）

先借后替。这些是核心竞争力，最终要内化。

| 能力 | 挂载方案 | 观察数据 | 替换判断 |
|------|----------|----------|----------|
| 技能系统 | 参考 Hermes skill 格式 | 30 天高频技能使用模式 | 70% 匹配 → 替换 |
| 代码审计 | 接 bandit + trivy（CLI） | 180 天审计结果 + 成功率 | > 90% → 省略 CLI 直接调 |
| 多模态理解 | llama-vision 11B (q4) | 图片描述质量 + 用户确认率 | > 85% → 固定为 internal |
| 模型推理 | llama.cpp / ollama | 模型切换频率 + 延迟 | 自己写 model_router |
| 消息网关 | 参考 OpenClaw 路由 | 消息分发模式 | 自己写 MCP bridge |

**投入**：挂载期 0 开发（pip install / git clone），观察期 Dream 系统自动分析，替换期每人月。

## 第三批：独特能力（3-6 月）

没有现成的，只能自己做。但可以观察外部 Agent 学。

| 能力 | 目标 | 学习来源 |
|------|------|----------|
| Agent 蒸馏 | 自动提取 + 内化 | 观察 Hermes / OpenCode 执行 |
| 调度自优化 | 路由越调越准 | Dream 分析调度日志 |
| 提示词凝练 | 高频 prompt → 模板 | Extractor 检测重复 |
| 安全审计 | 白名单 + AST + 沙箱 | 观察 Hermes 安全审计流程 |
| Web Ingest | 浏览器插件 | 自己写，无参考 |

**投入**：每模块 2-3 周，自研。

## 不做的

| 模块 | 为什么不做 |
|------|-----------|
| LanceDB / Chroma 等向量库 | FTS5 + LLM 替代，不引入新依赖 |
| RL 训练管线 | 太重，我们不做模型训练 |
| 多平台网关 | MCP 协议已足够，不重复造轮子 |
| 前端 UI | Dashboard HTML 够用 |

## 时间线

```
月 1: pip install 基础设施 → Nexus 核心跑通
月 2: 挂 Hermes 技能格式 → 跑 30 天
月 3: Dream 分析 → 生成第一批 internal 技能
月 4: 挂 llama-vision → 观察 30 天
月 5: agent_router 自优化 → 蒸馏第一批 Agent
月 6: 摘掉 60% 外部依赖 → internal 为主
```

## 判断标准

| 状态 | 条件 |
|------|------|
| 挂载 | 功能跑通，成功率 > 80% |
| 观察 | 30 天数据，Dream 分析完成 |
| 替换 | internal 版成功率 > 外部版 90% |
| 摘掉 | internal 版连续 30 天无回退到外部 |

每个外部模块一到时间点自动评估——决不是凭感觉说"差不多可以摘了"，而是成功率、用户反馈、Dream 分析三个数据都过门槛才摘掉。
