三、近期记忆窗口 & 冷热分层

近期 = 7 天。热数据放 HOT.md 独立索引，优先检索：

~/.omo/memory/
├── INDEX.md    # 全量（90条）
├── HOT.md      # 7天热索引（~20条）← 检索第一站
└── topics/
检索请求→ 先扫 HOT.md→ 不足 top_k→ fallback 全量 INDEX

store.py 写入时判断 ≤7 天 → 自动更新 HOT.md。Dream 只扫 hot。

五、代码索引方案分析

需求：给代码数据（函数签名/调用关系/模块依赖/类继承）建独立索引，通过 MCP Server 暴露。

✅ CodeGraphContext（推荐）

  • tree-sitter AST 解析，20 语言
  • KùzuDB 图数据库（零配置）
  • 内置 MCP Server + CLI
  • 调用链/死代码/复杂度分析
  • 增量更新 cgc watch
  • 3K+ Stars, MIT, v0.3.9
  • 部署: pip install

❌ 自研

  • 需逐个实现语言 AST parser
  • 需自选图数据库并集成
  • 需从零实现 MCP Server
  • 需自行实现 CLI 工具链
  • 维护全自担
  • 工期: 数周～数月

结论：直接用 CodeGraphContext。 功能完全覆盖，MCP Server 原生支持，与 sisyphus MCP 并列运行，agent 不感知背后有几个索引。自研的时间应该花在修 P0-P2 上。
