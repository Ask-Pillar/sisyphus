# Sisyphus 迭代规划 — 修 Bug + 逐步演进 > 日期: 2026-05-27 凌晨 > 原则: 能用现成的就用现成的，修地基优先，每步可验证 --- ## 零、原则 | 原则 | 说明 | |------|------| | **现成优先** | Python stdlib 有的不自己写（sqlite3），社区成熟的直接用（CodeGraphContext、Cytoscape.js、Chart.js） | | **小步验证** | 每步改完跑 `pytest`，不通过不进入下一步 | | **文件是 SSOT** | 所有索引都是可重建的派生品，丢了 `rm cache/ && rebuild` 就行 | | **先修地基** | P0 不修，上面盖什么都是歪的 | --- ## 二、Phase 2: 补架构层（预计 3-4 天） ### 2.1 P1-fts5: L3 SQLite FTS5 索引（论文承诺，你说要引入的） | | | |---|---| | 问题 | BM25 对中文查英文（"26号" vs "May 26"）无能为力。论文指定了 SQLite FTS5 | | 方案 | Python `sqlite3`（stdlib 内置）→ 建 FTS5 虚拟表 → 内存内容 + jieba 分词后写入。每次检索走 FTS5 MATCH，结果按 decay_score 排序 | | 用现成的 | **`sqlite3`（Python stdlib，零安装）** — Python 3.9+ 就有，不需要 pip install 任何东西。jieba 已经有了 | | 改动 | `src/sisyphus/memory/fts_index.py`（新建 ~80 行），`retrieval.py` 加 `_fts_search()` fallback | | 重建命令 | `python3 -m sisyphus rebuild` — 扫描所有 .md → jieba 分词 → 重建 FTS5，10 秒完成 | | 工作量 | **中（~100 行）** | | 验证 | 搜 "26号聊了什么" → 命中 "May 26" 标题的记忆。删 `cache/memory.db` → rebuild → 检索结果一致 | ### 2.2 P1-5: PERSIST 层 | | | |---|---| | 问题 | 核心决策和普通记忆混一起，可能被上下文窗口裁切掉 | | 方案 | Memory 加 `pinned` 字段。`before_turn()` 先加载 `pinned=True OR importance≥8` 的记忆，frozen 在 session 内不变（前缀缓存友好） | | 改动 | `store.py` Memory dataclass 加 `pinned`，`context.py` 加 `_load_persist()` | | 工作量 | **小（~30 行）** | | 验证 | pin 一条记忆 → `before_turn()` 返回的上下文第一条就是它 | ### 2.3 P1-8: 初始感知 | | | |---|---| | 问题 | `before_turn()` 不知道当前在哪个项目 | | 方案 | 第一次 turn 时自动跑 `git log -10 --oneline` + 目录树 + 上次会话摘要，注入 PERSIST 层 | | 改动 | `context.py` 加 `_sniff_project(cwd)` | | 工作量 | **极小（~15 行）** | | 验证 | 在 sisyphus 目录启动 → 上下文含 `git log` + `src/sisyphus/...` 结构 | ### 2.4 P1-4: 冷热分层 | | | |---|---| | 问题 | 每次检索扫全量，无 7 天优先 | | 方案 | 检索时先查 `created_at > now-7d`（HOT 池）→ 不够 top_k 再查全部（COLD 回退） | | 改动 | `retrieval.py` 改 `retrieve()`，加 `_hot_first()` | | 工作量 | **小（~20 行）** | | 验证 | 100 条记忆(10条7天内+90条旧的) → 搜一个关键词 → HOT 池 10 条命中优先返回 | --- ##
