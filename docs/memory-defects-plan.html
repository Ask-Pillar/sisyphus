P0

REFINED 层为空

Dream Engine（LLM 反思）和 Compressor（压缩）代码存在但从未产出结果。90 条 RAW 中 REFINED 仅 1 条。

RAW (90)→ Dream→ REFINED (1)

方案

  • 写集成测试：构造 5 条同 topic 记忆 → 触发 Dream → 验证产出
  • 检查 Dream/Compress handler 的 LLM 调用链路是否完整
  • 确保 Pipeline.run() 中 Dream/Compress 步骤实际执行

验证: 构造场景跑 Pipeline → REFINED 层新增 ≥1 条

P0

MemoryStore 和 MOC 写同一文件冲突

store.py 每次 CRUD 都 _rebuild_index() 写 INDEX.md（扁平），moc.py 也写同路径（wikilink 分组）。后来者覆盖前者，MOC 永不存在。

store.py → INDEX.md (扁平)  ──→ 被覆盖
moc.py   → INDEX.md (分组)  ──→ 被覆盖

方案

  • moc.py 输出到 MOC.md
  • store.py 只维护 INDEX.md
  • ContextRetriever 同时查询两个索引

验证: 写入 → moc 生成 → 两个文件独立存在

P1

Pipeline 无自动触发

Dream / Compress / TreeBuild 全需手动 run_pipeline，无自动触发。

方案

  • 新增 after_turn() → Pipeline.should_trigger()
  • 条件：新增 RAW ≥ N（默认 5）
  • 异步执行，不阻塞 agent 响应
  • 冷却期：30 分钟内不重复触发

验证: 连续写 5 条 → 下次 turn 自动触发 Dream

P1

会话不自动提取到记忆

对话结束后关键决策/教训不自动入 RAW，完全依赖手动 record。Agent session 关闭后上下文丢失。

方案

  • 实现 after_turn() 钩子
  • Extractor 接收 prompt + response，LLM 判断是否有决策/模式/教训
  • 有则自动 write_memory
  • 用轻量模型降 token 消耗

验证: 对话中做明确决策 → 下一 turn 前 RAW 出现对应记忆

P2

测试数据污染

90 条 RAW 中 69 条 "Test"，检索召回时冲淡有效结果。

方案

  • 检索时默认排除 tag:test
  • 或 delete_memory 加批量能力
  • CLI: memory.py clean --tag test

验证: 清理后 RAW ≈21，搜索无 Test 结果

实施顺序

P0-2 写冲突→ P0-1 REFINED→ P2-1 清理→ P1-1 自动触发→ P1-2 自动提取

P0-2 改动最小、影响最大（解耦后整个索引层才能工作）
P1-2 工作量最大，放最后
