三、差异化定位分析

🔵 Sisyphus 独有的

  • 三层架构（L1 .md → L2 .jsonl → L3 SQLite）— 全网唯一
  • 明文主存储 + SQLite 仅做索引 — git 可追踪，删库不丢数据
  • operations.jsonl 操作日志 — 审计溯源 + 时间旅行恢复
  • 四分区的注入策略（PERSIST 必加载 / HOT 优先 / COLD 衰减 / CODE 按需）
  • 中文原生支持（jieba 分词 + CJK 单字 fallback）
  • 代码索引集成（CodeGraphContext 图查询）

🟢 Sisyphus 追平主流

  • MCP Server 集成（所有对手都有）
  • 跨 session 持久化（行业标配）
  • 零依赖 / 本地优先 / 可自部署
  • FTS5 全文检索（open-mem 也有）

🟡 Sisyphus 落后 / 规划中

  • 自动捕获— agentmemory 12 hooks vs Sisyphus 未接入 Extractor
  • 后台反思— agentmemory hourly sweep vs Sisyphus Dream 未自动触发
  • 检索精度基准— agentmemory 95.2% R@5 有硬数据，Sisyphus 未测
  • 可视化— agentmemory :3113 Viewer / opencode-mem :4747 WebUI
  • 生态成熟度— Mem0 48K⭐ / agentmemory 9.3K⭐ / 文档社区
  • 去重 / 老化清扫— agentmemory 有 hourly sweep

🔴 Sisyphus 不需要的

  • 向量 DB 依赖— Qdrant/Neo4j/PGVector 等都是额外基础设施
  • Agent Runtime— Sisyphus 只做记忆，不做 agent 框架
  • Hard memory cap— Claude Code 200 行 / Hermes 2200 字符硬上限
  • 商业定价— Mem0 $249/mo Pro / Letta $200/mo

四、对照 agentmemory（最强竞品）深度拆解

agentmemory 是目前最接近 Sisyphus 的竞品——都做本地优先、零依赖、MCP 协议。但它俩的底层哲学完全不同：

维度agentmemory (9.3K⭐)Sisyphus
设计哲学 Memory Engine —"捕获一切，按需检索"
自动 hooks 抓取全量 agent 行为		 Context Assembler —"所有记忆 = 上下文组装"
.md 文件是源，SQLite 只是加速查询
存储架构 SQLite 主存储 + iii-engine 混合索引
数据只有一份，存在 SQLite 里		 L1 .md（源）→ L2 .jsonl（日志）→ L3 SQLite（索引）
数据三层冗余，各司其职
Git 友好 ❌ SQLite 二进制的，不能 diff ✅ L1 .md 明文，git diff/merge/blame 全部可用
审计 / 恢复 ❌ 无操作日志。删库 = 丢所有记忆 ✅ L2 operations.jsonl。删 L3 → 回放重建
始终加载 ❌ 无 PERSIST 层概念，全部检索召回 ✅ PERSIST 层每次 turn 无条件注入
自动捕获 ✅ 12 hooks 零手动调用。这是它最大优势 📋 Extractor 已写完但未接入。这是最大差距

代码索引 ❌ 纯记忆，不碰代码结构 ✅ CodeGraphContext 图索引（MCP 统一暴露）
部署成本 npm install + 12MB 下载 python3 直接跑，零安装
agentmemory 的核心优势是自动捕获 + benchmark 背书。它通过 12 个 hook 零手动调用地捕获 agent 行为，R@5 达到 95.2%。

Sisyphus 的核心优势是三层架构 + 明文可审计 + 中文原生。如果 agentmemory 是"记忆力最好的 agent 助手"，Sisyphus 更像是"适合严肃团队的记忆基础设施"——适合那些需要 git 追踪、审计、时间旅行、数据主权的中文团队。

五、Sisyphus 的差异化价值

Sisyphus 的不可替代性在于三层架构。 没有任何一个竞品同时做到这三件事：
能力谁有为什么重要
L1 明文 .md git 追踪 Hermes（部分）、@mathew-cf/memory（部分） 数据主权。不依赖专有格式，git diff/merge 全兼容，团队协作基础
L2 操作日志 + 时间旅行 ❌ 没有竞品 审计合规。能追溯到每个操作是谁在什么时候做的，能回滚到任意历史状态
L3 可丢弃的 SQLite 索引 ❌ 所有竞品用 SQLite 做主存储 索引层可以任意重建、切换、实验，不影响数据安全。删库不丢数据

六、Sisyphus 定位总结

📊 Sisyphus = 记忆系统的"三层架构"

对标类比说明
vs Mem0 (48K⭐)Sisyphus 更轻。不要向量 DB、不要图 DB、不要 API key。但 Mem0 的生态和成熟度碾压
vs Letta (22K⭐)Sisyphus 更专注。只做记忆，不做 agent runtime。Letta 锁入其运行时，Sisyphus 可配任何框架
vs agentmemory (9.3K⭐)Sisyphus 数据模型更丰富。三层架构 + 审计 + 分区策略是 agentmemory 没有的。但 agentmemory 的自动捕获 + benchmark 领先
vs opencode-mem (684⭐)Sisyphus 架构更彻底。不是插件级别的记忆系统，是自成体系的记忆基础设施
vs Claude CodeSisyphus 无硬上限。200 行 / 25KB 的限制不适合大规模，且闭源

一句话定位

Sisyphus 是目前唯一一个将"明文文件 git 追踪 + 操作日志审计 + SQLite 索引"三层拆开的记忆系统。 它不适合追求"开箱即用自动捕获"的场景（agentmemory 更适合）， 但适合那些需要数据主权、审计合规、中文原生、从第一天设计好大规模存储的场景。

如果要一句话说服别人用 Sisyphus

"你的 .md 文件就是数据库，SQLite 只是查询缓存——删了缓存，数据还在，git 还在，审计日志还在。"
