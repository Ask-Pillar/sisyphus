P0-1: REFINED 层为空

现状: RAW 90条(69条Test) → REFINED仅1条 → MOC 0。Dream 代码存在但从未实际运行出结果。

  • 写集成测试：构造 5 条同 topic 记忆 → 触发 Dream → 验证 REFINED 产出
  • 检查 Dream/Compress handler 的 LLM 调用链路
  • 确保 Pipeline.run() 实际执行 Dream/Compress（不是 skip）

P0-2: store.py 和 MOC 写同一文件冲突

store.py: _rebuild_index() → 写 INDEX.md（扁平格式）
moc.py:   generate()      → 写 INDEX.md（wikilink 分组格式）
→ 后来者覆盖前者。moc.py 输出永远不生效。

方案: moc.py 输出到 MOC.md，store.py 维护 INDEX.md，ContextRetriever 同时查两个索引。

P1-1: Pipeline 无自动触发

after_turn() 钩子 + task(run_in_background=true) 异步触发。Dream 只取未加工记忆(created_at > last_dream AND NOT refined_by AND NOT test)。LLM 后端: opencode subagent(默认)/DeepSeek Flash/Ollama/one-api。

P1-2: 会话不自动提取

Extractor 接收当前 turn 的 prompt+response → LLM 判断是否含决策/模式/教训 → 自动 write_memory。轻量模型避免每次 turn 大量 token 消耗。

1.3 architecture-redesign.md — 架构重设计

日期: 2026-05-24  |  核心: ContextRetriever → ContextAssembler

当前架构（问题）

AgentMemory.before_turn(query)
  └─ ContextRetriever → 单一 pipeline
       无 PERSIST 层，无 scene 感知，无 source 抽象

目标架构

ContextAssembler.assemble(query, scene="coding")
  ├─ Budget.allocate(total=8000)
  ├─ Source[0]: PERSIST (frozen, 无条件) → 2000 chars
  ├─ Source[1]: HOT (7天内, 按相关性) → 1800 chars
  ├─ Source[2]: SKILL (条件触发) → 800 chars
  ├─ Source[3]: CODE (scene=coding) → 1200 chars
  ├─ Source[4]: COLD (兜底) → 剩余配额
  └─ trim_to_budget()

改前 vs 改后

维度改前改后
PERSIST❌ 无✅ frozen, session 级缓存
HOT❌ 无独立概念✅ 7天优先
CODE❌ 无✅ CodeGraphContext Source
场景感知❌ 无✅ coding/planning/debugging
前缀缓存❌ 每次重新检索✅ PERSIST frozen

迁移路径（向后兼容）

Step 1: 加 Source 接口 + PERSIST Source
Step 2: 加 HOT Source + ContextAssembler
Step 3: 加 CODE Source (CodeGraphContext)
Step 4: 加 SKILL Source + scene 切换

1.5 context-is-everything.md — 一切记忆都是上下文组装

日期: 2026-05-24  |  核心洞察: "所有数据对于模型来说不过是提示词和上下文罢了"

所有记忆系统做同一件事

Mem0:    向量相似度 → top-k → 塞进 prompt
Letta:   pinned + 向量搜索 → 塞进 prompt
Hermes:  frozen MEMORY.md → 塞进 prompt
Claude:  MEMORY.md 索引 + 后台提取 → 塞进 prompt
Sisyphus: BM25 + LLM recall →  → 塞进 prompt

差异只在组装规则——先装什么、装多少、什么时候刷新。

概念统一

传统叫法实质
PERSIST 层每 turn 无条件 prepend 固定文本，配额 ≤2000 chars
HOT 索引按时间+相关性排序，挑 top-k
Dream离线预计算"将来可能用得上的好文本"
Compress离线把旧文本压缩成更短的等效文本
半衰期排序分数的时间权重
没有"记忆"这种东西，只有"上下文窗口的组装策略"。

1.6 embedded-vs-mcp.md — before_turn 内嵌 vs MCP

日期: 2026-05-24  |  核心: before_turn 是预处理，不是工具调用

9 个 MCP 工具，两类操作

被动（预处理，不该是 MCP）：
  get_context → 应该在 before_turn 里自动跑

主动（工具操作，适合 MCP）：
  write_memory, search_memory, get_memory, list_memories,
  delete_memory, run_pipeline, import_memories, memory_stats

推荐架构：混合

内嵌（Python import）: AgentMemory.before_turn() → PERSIST+HOT+CODE+COLD → 注入 prompt
                      AgentMemory.after_turn() → Extractor → 自动写 RAW

MCP Server（保留 8 个主动工具）: write/search/list/delete/stats/pipeline/import/get_memory
before_turn 不应该是一个工具调用，就像 import 不应该是一个 HTTP 请求。
